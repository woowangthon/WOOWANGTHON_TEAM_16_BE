## 공통 배치와 방법

- **보드**: TX-1(송신) 1대는 복도, RX-301은 223호, RX-302는 224호, RX-COR는 복도. 세 수신 보드를 게이트웨이(노트북 COM7)로 무선 수집(`--node RX-…=gw`)
- **사람**: 연기자 1명. 나머지는 감지 구역 밖 대기 장소. 223호·224호 문은 열어 둠
- **녹화**: `tools/collector.py session`. 장면 사이 20초 이동(`--countdown 20`), 장면마다 수신 보드 3개를 같은 시각으로 녹화
- **라벨**: 파일을 기록한 보드의 구역 기준. 사람이 223호에 누워 있으면 RX-301은 `lying`, RX-302·RX-COR는 `neighbor`
- **측정 구분**: 폴더 이름이 아니라 `.json`의 `day` 값(`2026-11-07`, `2026-11-07b`, `2026-11-07c`, `2026-11-07e`, `2026-11-07f`). 학습 코드는 `day`마다 그날의 빈 방으로 기준선을 따로 잡습니다
- **3·4차 화면**: 녹화하면서 같은 신호를 서버로 보내 화면에서 실시간 판단을 봄(watchmate-fe `scripts/record_live.py`). 서버에는 학습 모델 없이 1단계(신호 변화)만 켜고, 화면 판단 범위는 사람 측정됨 p ≥ 0.50 · 애매함 0.20~0.50 · 비어 있음 < 0.20

## 회차별 정리

### 1차 (`2026-11-07`)

**바꾼 것**: 첫 측정입니다. 보드 약 4m 간격, 223·224호 문 열어 둠.

**특수 상황**
- **RX-302만 받침 의자 높이가 달랐습니다.** RX-302 수신이 20~74Hz로 흔들렸고, 사람이 바닥에 가까울수록 덜 받았습니다(224호 서기 74 → 앉기 51 → 눕기 39Hz, 복도 눕기 29Hz, 223호 눕기 20Hz). 다른 두 보드는 76~88Hz로 안정적이었습니다.
- `standing_302` 녹화 중 화면 출력이 94초에서 멈췄습니다. PowerShell 창을 클릭해서 생긴 화면 멈춤이고, 데이터는 2분 모두 저장됐습니다(RX-COR 10,374프레임 ≈ 86Hz × 120초).
- 녹화 직전 점검에서 RX-301 무선 손실이 25.7%였지만 녹화 중에는 76~87Hz로 받았습니다.

**뺀 것**: RX-302의 `standing_302`·`sitting_302`·`lying_302`(파일 6개). 프레임이 빈 방의 70%보다 적게 들어온 2초 구간은 학습 코드가 어차피 빼지만, 남은 구간도 "프레임이 적으면 사람"을 배울 위험이 있어 통째로 뺐습니다. 224호 장면은 1차 보완으로 대체합니다.

### 1차 보완: 224호 다시 찍기 (`2026-11-07b`)

**바꾼 것**: **RX-302를 올린 의자를 다른 보드와 같은 높이의 의자로 바꿨습니다.** RX-302가 받는 TX-1 신호가 −56 → −47 dBm으로 강해졌고, 눕기도 82Hz로 빈 방(88Hz)과 거의 같아졌습니다. 224호 장면만 5개 찍었습니다.

**특수 상황**
- **끝 빈 방(`end_empty`)에서 RX-302 75%, RX-COR 34%가 "변화 큰 창"이었습니다.** 연기자가 나간 뒤에도 정적 반사가 처음과 달랐으니, 앉기·눕기 사이에 의자를 옮기고 원래 자리로 돌려놓지 않은 것으로 봅니다. 그래서 2차부터 의자를 테이프로 고정했습니다.
- RX-COR가 67~71Hz로 1차(86~88Hz)보다 낮았습니다. 장면끼리 차이는 없었습니다.

**뺀 것**: 없음. 다만 `end_empty`의 RX-302는 의자 위치가 처음과 다를 수 있습니다(`events.csv`).

### 2차 (`2026-11-07c`)

**바꾼 것**: **223·224호 의자 다리를 바닥에 테이프로 표시하고 녹화 내내 옮기지 않았습니다.** 서기와 눕기는 의자 옆 1m 테이프 자리에서 했습니다. 보드 높이는 1차 보완과 같습니다.

**특수 상황**
- **복도에 앉거나 누우면 방 보드도 반응했습니다.** 복도 앉기·눕기 때 RX-301 34%·93%, RX-302 68%·58%. 복도 서기 때는 0~7%였습니다. 바닥 가까운 몸이 복도의 TX-1에서 방으로 가는 신호를 가린 것으로 봅니다.
- **첫 빈 방(`start_empty`) 동안 무언가 움직인 것으로 보입니다.** RX-301·RX-COR는 빈 방 기준이 높게 잡혔고, RX-302는 기준이 아주 조용하게 잡혀 빈 방 장면에서도 32~47%가 나왔습니다.
- **223호 앉기(약 15:42–15:44) 때만 RX-COR 44%, RX-302 31%가 같이 반응했습니다.** 같은 방의 서기·눕기에는 반응이 없었으니, 그 사이 복도나 대기 장소에서 누가 움직였을 가능성이 큽니다.
- 수신은 세 보드 모두 76~88Hz로 고르게 받았습니다.

**뺀 것**: 없음. 위 장면들은 `events.csv`에 표시했습니다.

- 다섯 측정이 모두 같은 날이라 실제보다 후하게 채점될 수 있습니다.

## 측정에서 알게 된 것

1. **보드 높이를 모두 맞춥니다.** 한 보드만 높이가 다르면 바닥 가까운 몸에 수신이 끊깁니다(1차 RX-302).
2. **의자와 물건을 고정합니다.** 물건이 움직이면 빈 방도 "변화"로 잡힙니다(1차 보완 끝 빈 방).
3. **바닥 가까운 사람(눕기, 바닥 앉기)은 TX-1과 수신 보드를 잇는 선 근처에서 잘 잡힙니다.** 눕는 자리를 선 위로 옮기자 224호 눕기가 잡혔고(4차), RX-COR를 옮기자 같은 자리의 복도 앉기가 약해졌습니다. 보드를 옮기면 자리를 새 선 위에 다시 표시합니다.
4. **방 보드를 TX-1에서 멀리 두면 옆 구역 오탐이 줄어듭니다**(4차). 대신 게이트웨이까지 신호가 약해질 수 있어 녹화 전 점검이 필요합니다.
5. **측정마다 빈 방 보정이 필요합니다**(재보정 없이 오경보 0.99~1.00).

## 데이터 형식과 학습

장면 파일 하나 = `<day>_<노드>_<라벨>_<시각>_<번호>.csv` + 같은 이름 `.json`.

- `.csv`: `t`(수신 시각, 초), `rssi`, `data`(CSI 값 384개 = 서브캐리어 192개 × [허수, 실수])
- `.json`: `session_id`, `node`, `label`, `day`, `started_at`, `frames`, `seconds`, `scene`, `description`, `people`, `notes`, `recorded_with`, `node_restarts`, `raw_archive`
- 라벨: `empty`, `standing`, `sitting`, `lying`, `neighbor`(옆 구역에만 사람)

받은 묶음을 풀고 백엔드 폴더에서:

```bash
python -m app.ml.train --data <압축 푼 폴더>/학습용 --out models/presence_model.joblib
```

`학습용` 아래만 넣으세요. `제외` 폴더는 `.json`이 있어서 같이 넣으면 학습에 섞입니다. 비교표는 회차 폴더 하나로 봅니다.

```bash
python tools/collector.py compare --data <압축 푼 폴더>/학습용/4차_2026-11-07f
```

## 묶음 만들기(측정 노트북에서)

```bash
python tools/pack_field_data.py --data ../data --out ../watchmate_data_1107_all --zip
```

- 원본 폴더(`..\data\sessions`, `..\data\excluded`, `..\data\models`)는 읽기만 하고 복사합니다.
- `학습용/<회차>`, `제외/<묶음>`, `모델`, `장면목록`, `기록`(장면 로그, 화면 판단 CSV), `측정정리`(이 폴더의 CSV)와 파일 목록 `manifest.csv`를 만듭니다. `manifest.csv`에는 파일마다 회차, 장면, 초당 프레임, 학습 사용 여부, 특수 상황이 있습니다.
- 연속 원본(`_raw`)은 용량 때문에 빼고, 필요하면 `--with-raw`를 붙입니다.
- 회차마다 예상 파일 수와 다르면 경고합니다.

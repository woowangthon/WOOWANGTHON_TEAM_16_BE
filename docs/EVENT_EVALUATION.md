# 입장 반응과 준비 완료 장면의 유지율 평가

이 문서는 **실제 입장부터의 반응 시간**과 **준비가 끝난 관측 구간의 감지 유지율**을 구분하는 학습·평가 도구를 설명합니다. 번호가 바뀔 때 준비 20초 안에 이동과 자세 잡기를 마치는 실험 절차에 맞춰, 유지율에서 입장 후 20초와 퇴장 전 10초를 기본으로 추가 제외하지 않습니다. 실시간 감지는 계속되며 바뀌는 것은 평가 구간입니다. 이 도구를 추가한 것이 새로운 현장 성능을 입증한 것은 아닙니다.

기존 녹화의 `scene` 시작 시각은 실제 입장 시각과 다릅니다. 준비 중에 이미 들어와 자세를 잡았다면, 본 장면의 기록만으로 실제 입장 속도를 알 수 없습니다. 이때 입장 반응은 `unavailable`로 남기되, 관측자가 확인한 준비 완료 구간은 `settled_intervals`로 지정해 유지율을 평가할 수 있습니다. 장면 이름, 준비 시간 20초, 60초 길이, 첫 프레임, 신호 점수로 입장 시각을 대신 만들지 않습니다.

## 어떤 질문에 답하나

- 실제로 들어온 사건 중 몇 번을 정해진 시간 안에 감지했나?
- 감지한 사건은 몇 초 걸렸고, 늦게 감지하거나 놓친 사건은 몇 번인가?
- 자세를 잡고 머무는 안정 구간에서 감지가 얼마나 유지됐나?
- 사람이 없었다고 확인한 시간에 연속 경보가 몇 번 발생했나?
- 그 시간 중 판단 가능한 데이터가 얼마나 있었나?

2초 창의 재현율과 사건 성공률은 분모가 다릅니다. 서로 합치거나 같은 정확도라고 부르지 않습니다. 이 평가만으로 사람의 신원, 자세 분류 성능, 처음 보는 장소나 화재 현장의 성능을 입증하지도 않습니다.

## 실행

저장소 루트에서 실행합니다. 두 명령은 로컬 세션과 관측 정답을 읽는 ML 도구이며 서버의 실시간 상황과 분리되어 있습니다. 출력되는 숫자는 입력한 관측 자료의 평가 결과입니다. 도구를 실행했다는 사실만으로 새 현장 성능이 검증되지는 않습니다.

### 사람 판별 모델 없이 1단계만 평가

학습하거나 모델을 준비하지 않고 신호 변화의 입장 응답을 확인할 수 있습니다.

```bash
python -m app.ml.evaluate_events --data ../data/sessions --events ../data/event_annotations.json --out ../data/event_report.json --event-timeout-seconds 30 --evaluation-source measurement
```

결과 JSON의 `by_source.{source}.stage1_only`를 확인합니다. 선택한 출처와 `measurement`·`alarm` 비교를 함께 저장합니다. 이 보고서에는 사람 판별 모델 결과가 들어 있지 않습니다.

### 모델 학습과 함께 평가

```bash
python -m app.ml.train --data ../data/sessions --out models/presence_model.joblib --events ../data/event_annotations.json --event-timeout-seconds 30 --evaluation-source measurement
```

모델 카드의 `validation.event_evaluation`과 검증 fold의 `event_evaluation`을 확인합니다. `by_source`에는 선택한 출처와 함께 `measurement`·`alarm` 비교를 저장하고, 각 출처 안에서 `model`과 `stage1_only`를 나눕니다. 필요한 홀드아웃 모델이 없으면 모델 결과를 산출 불가로 남기며 학습 데이터 예측으로 대체하지 않습니다. 학습 검증 묶음(`day`)이 하나뿐일 때도 사건 전체를 빼고 학습한 모델이 없으므로 모델의 사건 평가는 `unavailable`이고, 1단계 사건 평가는 가능합니다.

### 공통 옵션

- `--data`: 수집 세션 폴더.
- `--events`: 사람이 관측해 작성한 사건 정답 JSON. 독립 평가 명령에서는 필수입니다. 학습 명령에서 생략하면 사건 평가를 계산하지 않습니다.
- `--out`: 독립 평가에서는 결과 JSON, 학습에서는 모델 파일을 저장할 경로.
- `--event-timeout-seconds`: 제시간 감지의 제한 시간. 기본은 **30초**이며, 정확히 30초인 감지도 포함합니다.
- `--evaluation-source`: 평가할 상황의 출처. `measurement`가 기본이고 `alarm`, `manual`, `replay`도 지정할 수 있습니다.

### 실측 기준과 운영 기준

모드에 따라 실제 화면이 쓰는 기준을 적용합니다. 모든 모드를 0.50으로 바꾸는 기능이 아닙니다.

| 평가 출처 | 모델 사용 (`model`, 사람 판별) | 모델 없이 비교 (`stage1_only`, 신호 변화) |
| --- | --- | --- |
| `measurement`, `replay` | 감지 0.70 / 가능성 0.35 | 큼 0.50 / 조금 0.20 |
| `alarm`, `manual` | 감지 0.70 / 가능성 0.35 | 큼 0.70 / 조금 0.35 |

실시간과 같은 평균 계산, 구역 안 노드 결합, 창 품질, 초기 준비 상태와 6초 신선도 규칙을 적용합니다. 초기의 미감지 판정에는 유효 창 3개가 필요합니다. 모델을 쓰지 않는 결과는 사람 존재 확률이 아니라 신호 변화에 대한 평가입니다.

## 관측 정답이 학습 창에도 적용되는 방식

학습에 `--events`를 주면, 주석에 연결된 세션은 장면 전체의 이름표 대신 관측 정답으로 창의 학습 라벨도 정합니다.

- 2초 창 전체가 명시적인 빈 방 구간 안에 들어가면 `empty`로 학습합니다.
- 2초 창 전체가 관측한 `pose_s` 이후부터 `exited_s` 전까지 들어가고, 사건의 `label`이 `PERSON_LABELS`에 속하면 그 라벨로 사람 학습에 씁니다. 예: `standing`, `sitting`, `lying`.
- 2초 창 전체가 확인한 `settled_intervals` 구간과 회차의 관측 범위 안에 들어가고, 구간의 `label`이 `PERSON_LABELS`에 속하면 그 라벨로 사람 학습에 씁니다. 이 구간으로 실제 입장 사건이나 입장 시각을 만들지는 않습니다.
- 입장부터 자세 정착 전까지, 자세 정착 시각을 모르는 구간, 경계를 걸친 창, 정답이 붙지 않은 구간은 해당 세션의 학습에서 제외합니다. 모델 카드의 `data.annotation_training_windows`에 사용·제외 집계를 남깁니다.

주석에 연결하지 않은 다른 세션은 기존 라벨 규칙을 사용합니다. 모델 학습에는 정답을 적용한 뒤에도 사람 있음·없음 자료가 모두 필요합니다. 학습할 수 없는 경우에는 독립 1단계 평가 명령으로 입장 반응을 확인할 수 있습니다.

이 학습용 제외를 사건 평가에 적용하지 않습니다. 입장 직후의 반응 시간과 품질 저하·무판단은 사건 관측에 남기므로, 학습에서 경계 창을 뺐다는 이유로 미탐이나 전체 사건 수가 줄어들지 않습니다.

## 정답 JSON

[관측 형식 예제](plans/event_annotations.example.json)는 **실제 측정이나 성능 결과가 아닙니다**. 예제의 세션 ID는 실제 파일에 존재하지 않는 이름표입니다. 파일을 복사한 뒤 `session_ids`, `origin_session_id`를 실제 메타데이터의 `session_id`로 바꾸고, 모든 시각과 구역도 직접 관측한 값으로 다시 작성해야 합니다. 예제를 그대로 넣어 세션 조회가 실패하는 것은 정상입니다.

### 구조

최상위에는 `schema_version: 1`과 `trials` 배열을 둡니다.

| 필드 | 뜻 |
| --- | --- |
| `trial_id` | 관측 회차를 구분하는 고유 ID |
| `zone_id` | 정답을 적용할 구역 이름표 |
| `session_ids` | 같은 구역에 속한 수신 녹화 세션 ID 목록 |
| `origin_session_id` | 공통 시계의 0초로 쓸 세션 ID. 해당 메타데이터의 `started_at` 사용 |
| `origin_epoch_s` | 공통 시계의 0초를 Unix epoch 초로 직접 지정할 때 사용 |
| `start_s`, `end_s` | 이 회차의 관측 시작과 끝. 공통 시계에 대한 상대 초 |
| `events` | 실제 입장 시각이 있는 사건 배열. 준비 완료 장면만 평가할 때는 빈 배열 가능 |
| `empty_intervals` | 사람이 없었다고 확인한 시간 구간 배열 |
| `settled_intervals` | 준비가 끝나 특정 자세로 머물렀다고 확인한 구간 배열. 선택 사항 |

`origin_session_id`와 `origin_epoch_s`는 **둘 중 하나만** 지정합니다. `origin_session_id`는 같은 회차의 `session_ids`에 포함되어야 합니다. 메타데이터의 `started_at`은 유한한 Unix epoch 초 숫자여야 하며, 없으면 오류입니다. `origin_epoch_s`도 유한한 숫자로 지정합니다. CSV 첫 프레임을 임의의 0초로 삼지 않습니다.

여러 수신기가 같은 구역을 관측했다면 한 `trial`의 `session_ids`에 모읍니다. 한 회차에는 노드마다 녹화 파일 하나만 지정합니다. 같은 노드의 여러 장면 파일을 한 회차에 섞으면 오류입니다. 입장 정답도 그 `trial`에 한 번만 작성합니다. 수신기 두 대가 본 한 번의 입장을 사건 두 번으로 세지 않습니다. 구역이 다르면 `trial`도 나눕니다.

모든 상대 시각은 **동일한 공통 시계**를 사용합니다. 각 수신 파일의 시작을 따로 0초로 바꿔 맞추지 않습니다. 예를 들어 기준 세션이 시작한 뒤 60초에 사람이 들어왔다면 `entered_s`는 60입니다. 절대 시각으로는 공통 원점의 epoch 초에 60을 더한 시각입니다.

회차의 관측 범위는 녹화 전체 중 일부여도 됩니다. 관측 시작 전의 최근 창은 평균 상태를 이어 받고 입장 전부터 감지 중이었는지 확인하는 이력으로만 사용합니다. 관측 시작 전이나 끝 이후의 시간을 사건 관측·안정 구간·빈 방 시간의 분모에 넣지 않습니다.

### 입장 사건과 빈 방

| 사건 필드 | 뜻 |
| --- | --- |
| `event_id` | 해당 회차 안에서 사건을 구분하는 ID |
| `entered_s` | 실제로 구역에 들어온 시각 |
| `pose_s` | 자세를 잡은 시각. 직접 관측한 경우에만 지정 |
| `exited_s` | 실제로 구역에서 나간 시각 |
| `label` | 직접 관측한 자세 등 설명용 분류. 선택 사항 |

`pose_s`를 모르면 생략하거나 `null`로 둡니다. 입장 시각을 자세 정착 시각으로 복사하지 않습니다. 해당 사건의 유지율은 산출할 수 없지만, 입장 응답은 가능한 범위에서 구분해 보여 줍니다. 실제 입장 시각이 관측 시작 전이라도 그 시각을 직접 기록했다면 `entered_s`에 그대로 넣을 수 있습니다. 재실 구간이 관측 범위와 겹쳐야 하며, 입장 반응은 `censored`, 사유는 `entry_before_observation`으로 표시합니다. 지연을 0초로 바꾸거나 장면 시작부터 다시 재지 않습니다.

`empty_intervals`는 `{ "start_s": 0, "end_s": 60 }`처럼 작성합니다. 사건 밖의 모든 시간을 자동으로 빈 방이라 간주하지 않습니다. 관측하지 못한 이동 시간이나 누가 들어왔는지 모르는 시간은 빈 방 정답에 넣지 않습니다.

### 준비 20초 안에 이미 이동·자세 잡기를 마친 경우

실제 입장 시각은 모르지만 본 장면 내내 자세를 유지했다는 관측이 있다면 `events: []`로 두고 `settled_intervals`를 사용합니다. 각 구간은 `start_s`, `end_s`와 선택적인 `label`로 적습니다. 예를 들어 장면의 0~60초를 직접 확인했다면 그 구간을 그대로 지정합니다. 준비가 20초라는 이유만으로 `entered_s: -20`이나 `pose_s: 0`을 만들어 넣지 않습니다.

이 구간은 관측한 유지율 평가에만 연결됩니다. 사람 라벨을 지정하면 관측 구간 안에 완전히 포함된 학습 창에도 쓸 수 있지만, 입장 횟수·첫 감지 지연·30초 성공률을 새로 만들지는 않습니다. 정확한 입장 사건을 알고 있다면 실제 시각을 `events`에 기록하고 같은 시간에 준비 완료 구간을 중복 지정하지 않습니다.

관측 형식 예제의 두 번째 회차가 이 경우입니다. 두 회차의 세션 이름표는 서로 다르며 모두 가상입니다. 예제의 0초는 관측 원점이지 실제 입장을 뜻하지 않습니다.

작성 시 확인할 점:

- `trial_id`와 회차 안의 `event_id`를 중복하지 않습니다.
- 같은 세션 ID를 서로 다른 회차에 다시 넣지 않습니다.
- 한 회차의 세션은 같은 학습 검증 묶음(`day`)에 속해야 합니다. 서로 다른 검증 fold의 파일을 섞으면 오류입니다.
- 실제 세션 ID가 맞는지, 공통 원점과 입장·자세·퇴장 순서가 맞는지 확인합니다. `pose_s: 0`도 실제 관측 시각이 0초라면 유효합니다. 0을 미상 표시로 사용하지 않습니다.
- 기준선 보정에 사용한 빈 방 구간을 다시 사건·오경보 평가에 넣지 않습니다. 빈 방 세션 전체를 보정에 썼다면 그 세션을 평가 회차에 지정할 수 없습니다. 빈 방 세션 하나를 앞쪽 보정·뒤쪽 평가로 나눈 경우에는 보정이 끝난 시각 이후에만 평가 회차를 시작할 수 있습니다.
- 입장 사건, 준비 완료 구간, 빈 방 구간이 서로 모순되거나 겹치지 않게 작성합니다. 실제 입장 사건으로 표현한 시간에 `settled_intervals`를 중복해서 붙이지 않습니다. 관측 끝 전에 나갔는지 확인하지 못했다면 퇴장을 관측 끝으로 만들어 넣지 않습니다.
- 사람 이름·학번·연락처는 필요하지 않습니다. 회차·구역·세션·사건 ID와 관측 시각만으로 연결합니다.

## 결과 읽기

### 제시간 감지와 감지 지연

입장 반응을 관측할 수 있는 사건의 기본 성공 조건은 **실제 입장 이후 30초 이내이면서 퇴장 전인 감지**입니다. 30초 경계는 포함합니다. 장면 시작부터의 시간이 아니며, 이미 끝난 사건의 감지를 다음 사건에 옮겨 세지 않습니다. 준비 중 입장부터의 속도를 평가하려면 그 실제 입장 시각과 그때의 신호 기록을 확보하고, 입장을 포함하는 관측 범위를 지정해야 합니다. `_raw`가 있다고 입장 정답이 자동으로 생기지는 않으며, 현재 세션 로더는 `_raw`를 자동 학습·평가하지 않습니다.

전체 사건 수와 다음 유형의 건수를 함께 봅니다. 유형별 합계가 전체 사건 수가 되도록 보고합니다.

| 유형 | 읽는 법 |
| --- | --- |
| `timely` | 설정한 제한 시간 안에 감지 |
| `late` | 제한 시간을 넘어서 감지 |
| `missed` | 유효 판단이 있었지만 체류 중 감지하지 못함 |
| `unjudged` | 유효 판단이 없어 감지 여부를 평가하지 못함 |
| `censored` | 입장이 관측 시작 전이거나, 필요한 관측 시간이 잘려 결과를 확정하지 못함. 준비 중 입장은 `entry_before_observation` 사유를 함께 표시 |
| `preexisting_detection` | 입장 전부터 감지 중이고, 이후 유효한 미감지를 거친 새 감지가 없어 이번 입장 반응으로 세지 못함 |

이 여섯 유형은 서로 겹치지 않습니다. 관측 시작 전 입장은 `censored`로 구분하고, 나머지 사건에서 유효 판단이 전혀 없으면 `unjudged`로 분류합니다. 전체 사건 수와 각 유형을 모두 남깁니다. 관측 시작 전 입장이 섞이면 전체 사건의 성공률(`timely_rate_all_events`, `detected_rate_all_events`)은 `null`이며 0%로 읽지 않습니다. 실제 입장부터 평가 가능한 사건 수(`n_entry_evaluable`)와 관측 시작 전 입장 수(`n_entry_before_observation`)를 따로 보여 줍니다.

`entry_response_status`는 입장 반응이 전부 평가 가능하면 `available`, 일부만 가능하면 `partial`, 하나도 평가할 수 없으면 `unavailable`입니다. 평가 가능한 사건만의 제시간 감지율은 `timely_rate_evaluable_events`, 감지율은 `detected_rate_evaluable_events`로 구분합니다. 이 분모에서도 해당 사건의 미탐·무판단·짧은 관측은 숨기지 않습니다. `events=[]`인 준비 완료 장면은 입장 사건 수와 입장 지연을 만들어 내지 않습니다.

감지 지연의 중앙값(`median_seconds_to_detect_successes`)은 **실제로 감지한 사건들에 조건부인 값**입니다. 제시간 감지와 늦은 감지를 산출 대상에 넣고, 그 대상 건수(`n_detected`)도 함께 표시합니다. 미탐을 0초로 넣거나 중앙값 계산에서 빠졌다는 사실을 숨기지 않습니다.

설명용 예를 들면, 입장 3번 중 2번을 4초·8초에 감지하고 한 번 놓쳤을 때 중앙값 6초만 쓰면 놓친 한 번이 보이지 않습니다. 전체 3번, 제시간 감지 2번, 미탐 1번과 함께 두 감지의 지연을 보여 줘야 합니다. **이 숫자는 설명용이며 실제 측정 결과가 아닙니다.**

### 준비 완료 구간의 감지 유지

번호 전환 시 준비 20초 안에 이동·자세 잡기를 마쳤다면, 본 장면에서 다시 20초를 빼지 않습니다. 고정된 끝 10초도 기본으로 제외하지 않습니다. 유지율 계산의 기본 `stable_after_s`와 `exit_margin_s`는 모두 **0초**입니다. 이 규칙은 감지를 기다리게 하거나 멈추는 설정이 아닙니다.

실제 입장 사건과 자세 정착 시각이 있는 경우에는 관측 범위와 겹치는 부분만 평가합니다.

- 시작: `pose_s`와 회차의 `start_s` 중 늦은 시각
- 끝: `exited_s`와 회차의 `end_s` 중 이른 시각

따라서 준비 중 이미 자세를 잡았고 본 장면이 0초에 시작했다면, 유지율의 분모도 관측 시작 0초부터입니다. 준비 중 시간이나 관측 종료 이후의 시간은 분모에 들어가지 않습니다. `pose_s`가 없거나 남는 구간이 없으면 그 사건의 유지율은 산출 불가입니다.

`settled_intervals`는 관측자가 확인한 시작~끝 구간을 그대로 평가합니다. 실제 입장이나 자세 정착의 순간을 모르는 준비 완료 장면도 이 방식으로 평가할 수 있습니다. 핵심 함수에 과거 규칙을 재현하는 지연·끝부분 제외 옵션을 명시하더라도, 명시적인 준비 완료 구간에는 그 옵션을 적용하지 않습니다.

집계의 `stable.status`는 유효 판단시간이 있으면 `available`, 유지 구간은 있지만 유효 판단시간이 0이면 `unjudged`, 평가할 유지 구간 자체가 없으면 `unavailable`입니다. 실제 입장 사건에서 얻은 유지 구간 수(`events_available`)와 별도 준비 완료 구간 수(`settled_intervals_available`)를 구분합니다. 입장 반응이 `unavailable`이어도 유지율은 산출할 수 있습니다. 산출 불가를 유지율 0% 또는 100%로 표시하지 않습니다.

전체 안정 시간(`total_s`), 유효 판단 시간(`valid_s`), 감지 유지 시간(`detected_s`)과 **coverage**를 함께 확인합니다. 기본 유지율(`hold_ratio`)은 감지 유지 시간을 전체 안정 시간으로 나눈 값이며, 무판단 시간도 전체 안정 시간에 포함합니다. coverage는 유효 판단 시간을 전체 안정 시간으로 나눈 값입니다. 별도로 제공되는 유효 판단 시간만을 분모로 한 유지율(`hold_ratio_known`)은 조건부 비율입니다. 안정 구간 밖의 창을 유지율 분모에 섞지 않습니다.

장면 CSV만 있으면 준비 중 실시간 판단의 평균 이력을 복원하지 못할 수 있습니다. 이때 장면 초반의 판단 자료 부족도 관측 구간과 coverage에 남깁니다. 초반 20초를 다시 빼거나 관측하지 않은 감지 상태로 채우지 않습니다.

### 빈 방의 연속 경보와 시간당 값

사람이 없다고 확인한 구간과 겹친 연속 감지를 경보 한 번(`episodes`)으로 셉니다. 2초마다 감지했다고 2초마다 새 오경보로 세지 않습니다. 무판단 구간만으로 경보가 끝났다고 단정하거나 새 경보 수를 늘리지 않습니다. 빈 방 구간 시작 전부터 이어지던 경보도 포함하며, 그 건수는 `carry_in_episodes`로 별도 표시합니다.

결과에는 경보 횟수, 전체 빈 방 관측시간, 유효 판단시간, coverage를 함께 남깁니다. 시간당 오경보(`episodes_per_valid_hour`)는 **유효 판단시간을 분모**로 계산합니다. 유효 판단시간이 0이면 시간당 값은 산출 불가이며, 오경보 0이라고 읽지 않습니다. `false_positive_ratio_known`은 유효한 빈 방 판단시간 중 감지 상태였던 시간 비율로, 경보 횟수와 다른 지표입니다. 긴 무판단 시간을 조용한 빈 방 시간으로 넣어 결과를 좋게 만들지 않습니다.

`windows`에는 회차 전체의 예상 2초 슬롯, 수신된 슬롯, 누락 슬롯과 저품질 창을 따로 남깁니다. 노드별 수신 슬롯 비율(`node_slot_coverage`)이나 받은 창의 품질 비율(`quality_coverage`)은 안정 구간·빈 방에서의 유효 판단시간 coverage와 분모가 다릅니다.

## 산출 가능 상태와 한계

- `available`: 해당 결과에 사용할 입장 사건·준비 완료 구간·빈 방 정답이 있어 관련 평가를 산출할 수 있음
- `partial`: 일부 회차나 비교 결과만 산출할 수 있으므로 누락 사유와 건수도 확인해야 함
- `unavailable`: 평가할 관측 정답이 없거나 독립된 홀드아웃 모델이 없어 해당 결과를 산출할 수 없음

실제 입장 정답은 있지만 기준선이 없거나 신호가 전혀 없는 경우, 1단계 평가는 그 입장을 `unjudged`로 남겨 전체 분모에 포함합니다. 모델 일부 회차만 평가할 수 있는 `partial` 결과에는 `annotated_events`, `unavailable_events`, `annotation_event_coverage`를 함께 표시합니다. 이때 `timely_rate_all_events`와 `detected_rate_all_events`는 산출 불가(`null`)이며, 계산 가능한 회차만의 비율은 `*_rate_evaluated_events`로 구분합니다.

준비 완료 장면은 입장 사건이 0건일 수도 있으므로, `annotated_trials`, `unavailable_trial_count`, `annotation_trial_coverage`로 평가한 회차의 범위도 표시합니다. 모델이 없어 빠진 회차가 있으면 `stable.scope`는 `evaluated_trials_only`이며, 유지율은 평가 가능한 회차만의 값입니다. 모든 회차를 포함하면 `all_annotated_trials`입니다. 사람이 있었다는 명시적 관측이 같은 수신기·측정 묶음의 빈 방 보정 시간과 겹치면 모순된 정답으로 거부합니다.

`available`은 성능 합격이나 현장 적용 가능을 뜻하지 않습니다. 30초는 명시적인 기본 평가 기준이며, 그 기준을 통과했다고 다른 날짜·사람·자리·화재 상황까지 검증된 것은 아닙니다. 한 날의 회차 ID를 나눴다면 그 결과는 실제 여러 날짜 검증과 구분해 설명합니다.

수집 PC의 epoch 시각을 상대 초로 변환할 때 생기는 부동소수점 오차를 고려해, 제한시간과 완전 관측 여부의 경계에만 1µs 허용 오차를 둡니다. 실제 측정이나 사람의 주석이 1µs 정밀도라는 뜻은 아닙니다.
